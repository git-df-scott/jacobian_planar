## 1. Why this route, and why now

The first Weyl algebra is A_1 = C<p,q> / ([p,q] - 1). Dixmier's Problem 1
(1968) asks whether every algebra endomorphism of A_1 is an automorphism
(DC_1). Endomorphisms of A_1 are automatically injective (A_1 is simple), so
the whole content is surjectivity.

[LIT] Tsuchimoto, and independently Belov-Kanel & Kontsevich, proved the
stable equivalence **DC_n <=> JC_{2n}**. In particular **DC_1 <=> JC_2**: the
Dixmier problem for the first Weyl algebra is *the same problem* as the plane
Jacobian conjecture this campaign is attacking.

The timing argument, which is what makes this worth writing down now.
Track E verified [LIT] that JC_n is **refuted for every n >= 3** (the 2026
Alpoge-Gallagher-Speyer-Gao line, with the two-dimensional case explicitly
untouched). Feeding that through the equivalence: JC_4 false => **DC_2 is
false**, and likewise DC_n is false for every n >= 2. So the Dixmier
conjecture, like the Jacobian conjecture, has collapsed to exactly one
surviving case, and it is the same case: n = 1 / dimension 2. Any Track W work
inherits the campaign's whole point rather than diverting from it.

A counterexample here is an endomorphism phi: A_1 -> A_1 that is not
surjective — equivalently a pair (P, Q) in A_1 with [Q, P] = 1 that does not
generate A_1.

## 2. The search object, stated precisely

Fix the Bernstein filtration: deg p = deg q = 1, F_k = span of normal-ordered
monomials p^i q^j with i + j <= k. An endomorphism is determined by
P := phi(q), Q := phi(p) subject to the single relation

    [Q, P] = 1.                                     (W)

Write, in the normal-ordered basis (all p's left of all q's — a basis of A_1,
so the expansion is unique):

    P = sum_{i+j <= d_P} a_{ij} p^i q^j ,
    Q = sum_{k+l <= d_Q} b_{kl} p^k q^l .

Expanding (W) in that basis gives a finite system of polynomial equations,
bilinear in (a, b), one per normal-ordered monomial — structurally the same
shape as the campaign's bracket systems, with the commutator playing the role
the Jacobian bracket plays there.

**Automorphism test.** (W) alone does not decide the question: every
automorphism satisfies it too. The counterexample condition is
"C<P, Q> != A_1", which is not directly a polynomial condition on (a, b). Two
usable encodings:

- **(W-a) Tame-orbit exclusion.** [LIT] Dixmier (1968) proved Aut(A_1) is
  generated by the elementary automorphisms
  (p, q) -> (p, q + f(p)) and (p, q) -> (p + g(q), q), together with the
  torus; i.e. Aut(A_1) is tame, with an amalgamated-product structure
  analogous to Jung-van der Kulk for Aut(C^2). A solution of (W) is therefore
  a counterexample **iff** it is not in the tame orbit of (p, q). Tameness is
  decidable degree-by-degree by the reduction algorithm implicit in the
  amalgam, so for any fixed degree budget this is a terminating test — the
  same role `jc2_bulletproof.py` plays for the polynomial side.
- **(W-b) Degree obstruction.** [LIT] The tame structure forces the degree
  pairs (deg P, deg Q) realizable by automorphisms to be exactly the
  "reducible" ones. Any solution of (W) whose degree pair is NOT of that form
  is automatically a non-automorphism. This is the direct analogue of the
  admissible-degree-pair analysis and is the cheap filter to run first.

## 3. The load-bearing observation for planning

Take the classical limit. Give A_1 the filtration above and pass to the
associated graded, a polynomial ring in two commuting variables with the
Poisson bracket induced by (1/hbar)[.,.]. The symbol of (W) at top order is

    {sigma(Q), sigma(P)} = 0   if deg P + deg Q - 2 > 0,

i.e. the leading forms are functionally dependent — **exactly the top-edge
condition this campaign already meets in the pentagon layer** (there:
[L_P, L_Q] = 0 forcing L_P = a S^2, L_Q = b S^3). Below the top, the
commutator's lower-order terms are the quantum corrections: additional
equations on the same unknowns, with no classical analogue.

Two planning consequences, and they point in opposite directions:

- **For a hunt** (finding a counterexample), Track W is *harder* than the
  polynomial route at equal degree: same leading-order combinatorics, strictly
  more equations. A Weyl counterexample is a plane-JC counterexample with
  extra conditions attached.
- **For a closure** (proving a degree range empty), Track W is *easier* at
  equal degree, for the same reason: the quantum corrections are free extra
  equations against the same unknowns. If a shape's classical layer survives
  but its quantum corrections do not, the Weyl formulation kills a case the
  polynomial formulation leaves open.

So the honest scoping verdict: **Track W is a closure tool, not a hunting
tool.** It should be pointed at whatever the polynomial route leaves alive,
not run as a parallel search. That is the opposite of how P5's one-line
description reads ("a non-automorphism endomorphism would disprove plane JC"),
and it is the thing worth a ruling.

## 4. What it would cost, if signed off

The machinery transfers with no new engine work:

- system builder — same shape as `trackA_gghv_system.py`; a normal-ordering
  routine replaces the bracket expansion, and the degree budget (d_P, d_Q)
  replaces the polygon vertex lists;
- reduction — `trackA_eliminator.py` verbatim (sound or-branching, replayable
  certificates);
- closure — the staged mod-p-then-exact-Q pipeline verbatim, including the
  leaf machinery now parametrized by `JCLEAF`;
- gate — `jc2_bulletproof.py` is polynomial-side; a Weyl candidate needs the
  (W-a) tame-reduction test as its gate, which does not exist yet and is the
  one genuinely new build. It is small (the amalgam reduction is an algorithm,
  not a search) and it is the thing to build first, because without it a
  "survivor" cannot be told from an automorphism.

Rough sizing before any commitment: at (d_P, d_Q) = (8, 12) — the pentagon
layer's own degrees — the unknown count is comparable to the case-(1) system's
186, and the equation count is larger than 302 because the quantum corrections
add one equation per lower-order monomial. In other words the first honest
Track W instance is *at least* as big as the object that is currently STALLED
in P0. That is the main argument against starting it now.
